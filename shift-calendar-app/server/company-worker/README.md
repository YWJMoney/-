# 밤낮 회사 규칙 서버 (bamnat-company)

같은 회사 사람들이 근무 설정과 급여 계산 방식을 나눠 쓰는 서버예요. 금액은 오가지 않아요.
개발자 앱은 같은 주소의 `/admin/`에 있어요 [COMM-04][COMM-01][COMM-02][COMM-03][ADMIN-01].

Cloudflare 무료 요금제로 충분해요. 공유 링크 서버(`server/share-worker`)와는 따로 올려요.

## 배포하기 (Cloudflare 대시보드)

공유 링크 서버를 올린 같은 Cloudflare 계정에서 해요.

1. **D1 데이터베이스 만들기**
   왼쪽 메뉴 저장소 및 데이터베이스(Storage & databases) → D1 SQL 데이터베이스 → 데이터베이스 만들기(Create).
   이름은 `bamnat-company`로 해요. 표는 서버가 처음 쓸 때 스스로 만들어요.
2. **Worker 만들기**
   컴퓨팅(Workers) → Workers 및 Pages → 만들기(Create) → Worker → Hello World로 시작.
   이름을 `bamnat-company`로 하고 배포(Deploy)를 눌러요.
3. **코드 붙여 넣기**
   만든 Worker에서 코드 편집(Edit code)을 눌러요. `worker.js` 내용을 모두 지우고 출시용 `worker.js` 전체를 붙여 넣은 뒤 배포(Deploy)를 눌러요.
   출시용 `worker.js`는 이 폴더에서 `npm run bundle`로 만들어요(`dist/worker.js`). `src/index.js`와 개발자 앱 화면(`src/admin-app.js`)을 한 파일로 합친 거예요.
4. **데이터베이스 연결**
   Worker 화면의 바인딩(Bindings) → 바인딩 추가(Add binding) → D1 데이터베이스.
   변수 이름은 `DB`, 데이터베이스는 `bamnat-company`를 골라요.
5. **비밀값 두 개 넣기**
   `bamnat-company` Worker → 설정(Settings) → 런타임 변수(Runtime variables) → 변수 추가(Add variable).
   화면에 따라 변수 및 비밀(Variables and Secrets) → 추가(Add)로 보이기도 해요. 환경은 Production에 체크해 두고,
   줄마다 Secret에 체크해요. 두 번째 줄은 + Add로 만들어요.
   - `ADMIN_PASSWORD`: 개발자 앱 비밀번호예요. 10자 이상으로 직접 정해요.
   - `RATE_SALT`: 아무 긴 글자예요. 비밀번호 생성기로 만든 32자 정도면 돼요. 공유 링크 서버의 것과 달라도 돼요.

   Key는 대문자와 밑줄 그대로, 앞뒤 빈칸 없이 써요. 마지막에 파란 Add variable and deploy(배포)를 눌러야 서버가 읽어요.
   옆 화살표 메뉴의 저장만 하는 버튼은 배포가 되지 않아요.
   같은 설정 화면 아래쪽 빌드(Build)의 변수 칸이나 왼쪽 메뉴의 Secrets Store에 넣은 값은 서버가 읽지 못해요.
   서버가 비밀번호를 읽기 전에는 로그인 화면의 입력칸이 잠겨 있어요.
   두 값 모두 채팅이나 메신저로 보내지 마세요.
6. **확인**
   휴대폰 크롬 주소창에 `https://bamnat-company.<계정 이름>.workers.dev/admin/`을 그대로 입력해요. 검색으로는 나오지 않아요.
   `<계정 이름>`은 비밀값이 아니라 Cloudflare가 정한 workers.dev 이름이에요. 공유 링크 서버 주소(`bamnat-share.<계정 이름>.workers.dev`)의 가운데와 같고,
   Worker → 설정(Settings) → 도메인 및 경로(Domains & Routes)에도 전체 주소가 나와요. RATE_SALT는 주소에 넣지 않아요.
   빠진 설정이 있으면 로그인 화면 아래 "서버 준비"에 무엇을 하면 되는지 나와요.
   로그인한 뒤 크롬 메뉴(⋮) → 홈 화면에 추가를 누르면 앱처럼 열려요.
7. **주소 알려 주기**
   workers.dev 주소만 Claude에게 알려 주세요. 앱 연결은 Claude가 해요. 비밀번호와 RATE_SALT는 알려 주지 않아요.

코드를 고친 뒤에는 3번만 다시 하면 돼요. 데이터베이스와 비밀값은 그대로 남아요.

## 개발자 앱 (/admin)

휴대폰, 펼친 폴드, 컴퓨터에서 같은 주소로 열려요. 폰은 아래 탭, 폴드와 태블릿은 왼쪽 레일, 컴퓨터는 사이드바로 바뀌고, 휴대폰 글자 크기를 키워도 줄이 넘치지 않게 따라 커져요.
크롬이나 삼성 인터넷에서 앱 설치(홈 화면에 추가)를 누르면 스토어 없이 앱으로 설치돼요. 설치 방법은 `/admin/install`에 있어요.

| 화면 | 하는 일 |
| --- | --- |
| 홈 | 지금 할 일, 기다리는 것 숫자, 최근 활동. 1분마다, 앱으로 돌아올 때마다 숫자를 새로 받아요. |
| 문의 | 앱 안 문의와 문제 신고. 대화로 보고 답하거나 답하고 닫아요. 자주 쓰는 답을 눌러 넣을 수 있어요. |
| 관리자 | 최고 관리자만. 관리자 초대, 승인, 권한 바꾸기, 멈추기, 삭제. |
| 활동 기록 | 누가 언제 무엇을 했는지. 1년 지난 기록은 지워져요. |
| 검토 | 같은 규칙끼리 묶인 제보, 채택 점수, 지금 쓰는 규칙과 다른 점을 봐요. 채택하거나, 이유를 골라 거절해요. 거절 이유는 보낸 분 앱에 보여요. "달라요"가 달린 규칙도 여기 모여요. 앱으로 설정하지 못한 방식은 "앱에 없는 방식"에 모이고, 답을 고르면 보낸 분 앱에 보여요. 앱에 넣을 방식이면 보상도 기록할 수 있어요. |
| 토론 | 앱 사용자가 규칙마다 남긴 글 [COMM-06]. 신고된 글이 먼저 보이고, 가리기(이유는 글쓴이 앱에 보여요)·다시 보이기·지우기·30일 쓰기 막기를 해요. 검토 카드의 "토론 읽기"로 한 규칙의 글 전부를 봐요. |
| 회사 | 이름 바꾸기(예전 이름으로도 찾아져요), 다른 이름(영문·줄임말) 넣기, 회사 찾기에서 숨기기, 규칙 내리기·다시 올리기, 두 이름으로 생긴 같은 회사 합치기. |
| 보상 | 채택된 정보를 보낸 분들께 드릴 프로 이용 기간이에요. 지급함·취소를 기록해요. 스토어 리뷰와는 묶지 않아요. |
| 설정 | 자동 채택 점수(2~20점, 처음 3점)와 채택 보상(0~24개월, 처음 3개월). 앱 설치. 서버 상태(최고 관리자). |

키보드가 있으면 숫자 1~9로 화면을 옮기고, `/`로 찾기 칸, `R`로 새로 고침, `?`로 단축키 목록을 봐요.

## 관리자 계정과 권한 [ADMIN-04]

- **최고 관리자**는 `ADMIN_PASSWORD`로 로그인하는 사람이에요(로그인 화면의 "최고 관리자" 탭). 모든 화면을 쓰고, 관리자를 초대·승인하는 건 최고 관리자만 해요.
- **관리자 계정**은 아무나 만들 수 없어요.
  1. 최고 관리자가 관리자 화면에서 메일과 권한을 정하고 초대 링크를 만들어요. 링크는 한 번만 보이고 7일 동안 열려요. 서버에는 해시로만 남아요.
  2. 그 링크를 그 메일로 보내요("메일로 보내기"는 메일 앱을 열어요). 링크는 그 메일 하나에만 쓰여요.
  3. 링크를 연 분이 이름과 비밀번호(10자 이상)를 정해 계정을 만들고, 앱을 설치해요. 계정은 "승인 대기"로 시작해요.
  4. 최고 관리자가 승인하면 그때부터 메일과 비밀번호로 로그인돼요.
- **권한**은 영역마다 없음·보기·고치기 중에서 골라요: 검토, 문의, 회사·규칙, 보상, 채택 설정, 활동 기록(보기만). 운영 관리자·검토 담당·문의 담당·보기 전용으로 한 번에 고를 수도 있어요.
  권한을 바꾸거나 멈추거나 삭제하면 바로 적용돼요. 멈추거나 삭제한 계정은 그 자리에서 로그아웃돼요. 서버에 새로 생긴 경로는 권한을 정하기 전까지 최고 관리자만 써요.
- 비밀번호는 PBKDF2 해시로만 남아요. 한 계정에서 5번 틀리면 어느 네트워크에서든 1시간 잠겨요. 관리자는 내 계정에서 비밀번호를 바꾸고 모든 기기에서 로그아웃할 수 있어요.
- **메일 확인 코드(선택)**: Worker 비밀값에 `MAIL_API_KEY`(Resend의 API 키)와 `MAIL_FROM`(예: `밤낮 <no-reply@내도메인>`, Resend에서 확인한 도메인)을 넣으면,
  가입할 때 초대받은 메일로 6자리 코드가 가고 코드를 넣어야 계정이 만들어져요. `OWNER_EMAIL`을 넣으면 누가 가입했을 때 최고 관리자에게 알림 메일이 가요.
  넣지 않으면 서버는 메일을 보내지 않고, 초대 링크를 메일로 보내는 것이 메일 확인이에요.
- 이 버전으로 바꾸면 예전 로그인은 한 번 끝나요. 최고 관리자 탭에서 다시 로그인하면 돼요.

## 채택되는 방식

- 같은 회사, 같은 부서, 같은 규칙을 서로 다른 2명 이상이 보내 점수가 채택 점수에 닿으면 자동으로 채택돼요.
- 근무 시간과 순서, 연장·휴무일 근무 방식, 가산율, 감시·단속 승인과 휴게 같은 회사 규칙, 수당 방식이 같으면 같은 규칙이에요. 근무 이름, 색, 순서를 시작한 날짜는 따지지 않아요.
- 투표한 분 가운데 맞았어요가 정한 비율(처음 75%, 설정에서 50~100%) 이상이어야 자동으로 채택돼요. 모자라면 검토에 남아 개발자가 정해요 [COMM-07].
- 앱의 신뢰도(0~100)는 맞았어요 비율 × 채택 점수를 채운 정도예요.
- 명세서로 맞춰 본 제보는 2점, 그 밖의 제보는 1점이에요. 다른 분의 "맞았어요"는 1점이고, 명세서로 맞춰 봤다면 2점이에요. 한 휴대폰은 한 번만 세요. "달라요"를 누른 분의 점수는 빠져요.
- 모두 1시간 안에 같은 네트워크(회사 와이파이 등)에서 보낸 설정은 자동으로 채택하지 않고 개발자가 확인해요. 한 분이 여러 번 보냈을 수도 있어서예요.
- 이미 쓰는 규칙이 있으면 바꾸는 건 개발자가 정해요. 개발자가 거절하거나 내린 설정도 다시 모여도 자동으로 채택되지 않아요.
- 채택되면 그때까지 보낸 분마다 보상이 "지급 대기"로 기록돼요.
- "앱에 없는 방식"으로 보낸 것은 점수에 들어가지 않고 개발자만 봐요. 개발자가 "앱에 넣을게요"로 답하면 보상을 기록할 수 있어요.

## 개인정보

- 기본급, 수당 금액, 1회 정액, 입사일, 연차, 알람, 달력 날짜는 받지 않아요. 금액이 들어 있는 파일은 지워서 받지 않고 통째로 거절해요.
- 회사 이름, 부서, 메모, 근무·수당 이름에 전화번호, 이메일, 금액이 보이면 거절해요.
- IP 주소는 저장하지 않아요. 보내기 제한과 "같은 네트워크" 판단에는 RATE_SALT를 섞은 해시만 쓰고 2시간 안에 지워요. 그 뒤에는 같은 네트워크에서 1시간 안에 보낸 것끼리 묶는 무작위 표시만 남아요.
- 앱 설치 ID는 해시로만 남겨요. 보낸 분은 앱에서 제보를 되돌리거나 보낸 것 전부를 지울 수 있어요.
- 토론 글: 다른 사용자에게는 그 토론 안의 "참여자 N"과 올린 분·맞았어요·달라요·명세서 확인 표시만 보여요. 설치 해시는 개발자 앱에 앞 6자만 보여요.
  이메일·전화번호·금액이 보이는 글은 거절해요. 서로 다른 3명이 신고하면 개발자가 볼 때까지 가려지고, 가린 글은 90일 뒤 지워요. 내 데이터 지우기는 글과 신고도 지워요.
- 제한: 토론 글은 설치마다 하루 20개, 네트워크마다 60개. 설치마다 하루 10건, 네트워크마다 하루 30건, 투표는 1시간에 60건, 제보 하나는 32KB까지예요. 관리자 비밀번호를 5번 틀리면 그 네트워크는 1시간 동안 잠겨요.

## 앱이 쓰는 API

| 요청 | 하는 일 |
| --- | --- |
| `GET /api/companies?q=` | 회사 찾기. 띄어쓰기, (주), 주식회사, Co., Ltd.는 빼고 찾아요. 아직 확인 중인 회사는 이름이 똑같을 때만 나와요. |
| `GET /api/companies/:id` | 회사의 채택된 설정과 확인 중인 설정, 각 설정을 풀어 쓴 줄(`lines`) |
| `GET /api/terms` | 채택 점수와 채택 보상 기간 (보내기 전에 앱이 보여 줘요) |
| `POST /api/reports` | 제보 보내기 `{v: 1, device, company, dept, verified, note, setup}`. 앱에 없는 방식이면 `ask: true`와 설명(1500자까지)을 `note`에 |
| `GET /api/reports/:id` | 제보가 어디까지 왔는지: 점수, 채택, 거절 이유, 보상 |
| `DELETE /api/reports/:id` | 제보 되돌리기 (헤더 `X-Device`) |
| `DELETE /api/mine` | 이 설치가 보낸 것 전부 지우기 (헤더 `X-Device`) |
| `POST /api/votes` | 맞았어요·달라요 `{device, company, setup, ok, verified?, why?}` |
| `GET /api/board?tab=voting\|adopted&from=` | 회사 규칙 광장: 모든 회사의 투표 중인 규칙(최근 활동 순)이나 채택된 규칙, 20개씩 [COMM-07] |
| `GET /api/companies/:id/setups/:setup/posts` | 한 규칙의 토론. 헤더 `X-Device`가 있으면 내 글 표시와 가려진 내 글의 이유 [COMM-06] |
| `POST /api/posts` | 토론 글 `{device, company, setup, body}` (500자까지) |
| `DELETE /api/posts/:id` | 내 글 지우기 (헤더 `X-Device`) |
| `POST /api/posts/:id/flag` | 신고 `{device, reason: abuse\|personal\|spam\|false}` |

설정 파일은 버전 3까지 받아요. 감시·단속 승인, 5인 미만 공휴일, 유급 휴게, 가산 대신 받는 수당을 쓴 설정만 3이 되고, 나머지는 예전 앱도 읽는 2로 남아요.

```sh
ADMIN_PASSWORD=<10자 이상> npm run local -- 8788 --seed
```

`--seed`는 지어낸 회사들의 제보와 관리자(승인된 민지, 승인 대기 준호, 가입 전 초대 하나)를 넣어서 모든 화면에 뭔가 보이게 해요. 민지는 `minji@example.com` / `minji-review-2026`으로 로그인해요. 개발자 앱은 `http://localhost:8788/admin/`에서 열려요.
