# 밤낮 근무표 공유 서버 (bamnat-share)

‘링크로 보내기’로 만든 근무표를 브라우저와 밤낮 앱에 보여 주는 서버예요 [MKT-09][SHR-01][SHR-02].
Cloudflare Worker 하나와 KV 저장소 하나로 돌아가고, 무료 요금제로 충분해요.

## 앱 1.10을 내기 전에: 코드 다시 올리기

앱 1.10의 ‘받은 근무표’는 이 서버의 새 주소(`GET /api/share/:id`)로 근무표를 읽어요.
**스토어에 1.10을 올리기 전에** 서버를 먼저 새 코드로 바꿔 주세요. 예전 서버에서는 받은 링크를 넣으면
"근무표를 받지 못했어요"가 나와요. 새 서버는 예전 앱이 만든 링크도 그대로 받아요.

1. Cloudflare 대시보드 → 컴퓨팅(Workers) → Workers 및 Pages → `bamnat-share`를 열어요.
2. 코드 편집(Edit code)을 눌러 `worker.js` 내용을 모두 지우고, 이 폴더의 `src/index.js` 전체를 붙여 넣은 뒤 배포(Deploy)를 눌러요.
3. KV 바인딩(`SHARES`)과 비밀값(`RATE_SALT`)은 그대로 남아요. 다시 넣지 않아도 돼요.
4. 확인: `https://bamnat-share.<계정 이름>.workers.dev/.well-known/assetlinks.json`을 열어 `[]`가 보이면 새 코드예요.

## 선택: 링크를 누르면 바로 앱으로 열기 (ANDROID_CERT_SHA256)

넣지 않아도 공유 페이지의 "밤낮 앱에서 보기" 버튼으로 앱이 열려요. 넣으면 메신저에서 링크를 누를 때 브라우저를 거치지 않고 바로 앱이 열려요.

1. Play Console → 앱 → 테스트 및 출시(Test and release) → 앱 무결성(App integrity) → 앱 서명(App signing)에서
   **앱 서명 키 인증서**의 SHA-256 인증서 지문을 복사해요. `AB:CD:…` 모양의 64자리예요.
2. Worker → 설정(Settings) → 변수 및 비밀(Variables and Secrets) → 추가(Add). 유형은 **텍스트(Text)**,
   이름은 `ANDROID_CERT_SHA256`, 값은 복사한 지문이에요. 직접 빌드한 앱도 열리게 하려면 업로드 키 지문을 쉼표로 이어 붙여요.
3. 배포(Deploy) 후 `/.well-known/assetlinks.json`에 지문이 보이면 돼요. 휴대폰이 확인하는 데 하루쯤 걸릴 수 있어요.

이 지문은 공개 정보라 비밀은 아니에요. 그래도 Claude에게 따로 보낼 필요는 없어요.
`RATE_SALT`는 비밀값이니 채팅이나 메신저로 보내지 마세요.

## 앱이 쓰는 API

| 요청 | 하는 일 |
| --- | --- |
| `POST /api/share` | 링크 만들기. 답: `{id, url, deleteToken, expiresAt}` |
| `PUT /api/share/:id` | 지금 근무표로 고치기 (헤더 `X-Delete-Token`). `ttlDays`가 없으면 끝나는 날을 그대로 두고, 있으면 오늘부터 그만큼 열어요 |
| `DELETE /api/share/:id` | 링크 끊기 (헤더 `X-Delete-Token`) |
| `GET /api/share/:id` | 받은 근무표 읽기. 답: `{schedule, expiresAt, updatedAt}`와 `ETag`. `If-None-Match`에 그 값을 넣으면 바뀐 게 없을 때 304. 끊겼거나 기간이 지나면 404 `not_found` |
| `GET /s/:id` | 브라우저로 보는 근무표 페이지 (검색엔진 차단, 스크립트 없음) |
| `GET /s/:id.ics` | [FEAT-15] 같은 근무를 캘린더 앱이 구독하는 iCalendar 형식으로 (공유한 사람이 ‘캘린더 구독 주소’를 켰을 때만, 아니면 404) |
| `GET /.well-known/assetlinks.json` | 링크를 앱으로 여는 Android 확인 파일 |

근무표 형식은 `v: 1`(근무와 휴가만)과 `v: 2`(보낸 분이 고른 것을 `shows`에 함께)예요.
`shows`에는 `leaveKinds`, `extras`, `memos`, `pay`가 들어갈 수 있고, 서버는 고르지 않은 항목이 오면 버려요.
휴가 종류(`leaveKinds`)를 고르지 않으면 휴가는 연차가 아닌 한 '휴가'·'반차'처럼 쉬는 만큼만 남겨요.
날마다 `rest`(링크에 담긴 것으로 본 쉬는 날인지)가 함께 와서 앱이 같이 쉬는 날을 보여 줘요.
근무가 없는 날도 대근이 있으면 `second`만으로 들어와요.

앱 1.13부터 [SHR-11]:
- `pay`에 담긴 금액이 무엇인지 `payKind`로 와요. `pay`(직원 급여), `jobs`(현장·프리랜서 일감 수입), `sales`(자영업 매출). 없으면 `pay`예요.
  페이지는 "함께 보낸 매출"처럼 그 이름으로 보여 줘요.
- `shows`에 `jobs`(일정)가 더해졌어요. 날마다 `jobs: [{name, time}]`가 4개까지 오고, 이름은 12자까지예요. 고객·장소·금액은 받지 않아요.
- 근무가 없는 달력(가게, 현장 일)은 `days`가 비어 있어도 금액(`pay`)이 있으면 받아요.
- **앱 1.13을 내기 전에 이 서버 코드를 다시 올려 주세요.** 예전 서버는 일정과 근무 없는 링크를 거절해요(앱이 "보낼 근무가 없어요"라고 알려 줘요).

앱 1.14부터 [SHR-12]:
- 공유한 사람이 달력을 고치면 앱이 몇 초 뒤 링크를 스스로 고쳐요(`PUT`에 `ttlDays` 없이). 이때 링크가 닫히는 날은 그대로예요.
  같은 내용을 다시 보내면 `updatedAt`도 그대로라 받은 사람 앱이 다시 내려받지 않아요.
- 기간 늘리기(앱 공유 화면, 또는 닫히기 3일 전 알림의 ‘N일 늘리기’)는 `ttlDays`를 넣어 보내요. 오늘부터 7·30·90일이에요.
- 받은 사람 앱은 `ETag`를 넣어 물어보고, 바뀐 게 있을 때만 근무표를 받아요. 근무표가 바뀌거나 기간이 늘면 `ETag`가 바뀌어요.
- 이미 닫힌 링크는 `PUT`으로 다시 열 수 없어요(404).
- **앱 1.14를 내기 전에 이 서버 코드를 다시 올려 주세요.** 예전 서버는 `ttlDays` 없는 고치기를 30일로 바꿔서, 자동 고치기 때마다 끝나는 날이 30일 뒤로 바뀌어요.

앱 1.20부터 [PROV-04][FEAT-15]:
- `ttlDays`에 180과 365가 더해졌어요(앱에서는 프로). 예전 서버는 이 값을 거절해서 1년 링크를 만들 수 없어요.
- 보낼 때 `ics: true`와 `tz`(휴대폰의 시간대 이름, 예: `Asia/Seoul`)가 오면 `GET /s/:id.ics`가 열려요. `tz`는 `지역/도시` 모양만 받고, 없으면 `Asia/Seoul`이에요.
  `ics`가 없는 고치기가 오면 구독 주소는 닫혀요(앱에서 끄거나 프로가 끝났을 때).
- 구독 파일에는 근무가 있는 날마다 일정 하나(근무 시간, 없으면 하루 종일), 대근·시간 있는 연장 근무, 휴가가 들어가요. 쉬는 날은 넣지 않아요.
  같은 날짜의 일정은 UID가 같아서 근무를 바꾸면 구독한 캘린더에서도 그 일정이 바뀌어요. 페이지에 보이는 것보다 더 많이 담지 않아요.
- 캘린더 앱에 6시간마다 다시 읽으라고 알려 주지만(`REFRESH-INTERVAL`), 실제로 언제 읽는지는 캘린더 앱이 정해요. 구글 캘린더는 몇 시간에서 하루쯤 걸려요.
- **앱 1.20을 내기 전에 이 서버 코드를 다시 올려 주세요.**

## 개인정보

- 근무 이름·색·시간과 날짜, 쉬는 날인지, 보낸 분이 고른 것(휴가 종류, 연장·휴무일 근무, 메모 첫 줄 80자, 달마다 세전 급여 하나)만 저장해요.
- 링크는 고른 기간(7·30·90·180일·1년)이 지나거나 ‘링크 끊기’를 누르면 지워져요. 받은 사람 앱의 근무표도 그때 지워져요.
- IP 주소는 저장하지 않아요. 링크 만들기 제한에는 `RATE_SALT`를 섞은 해시만 쓰고 한 시간 안에 지워요.
- 받은 근무표를 읽을 때는 아무것도 저장하지 않아요.
- 구독 주소를 켜면 시간대 이름 하나를 더 저장해요. 구독하는 캘린더가 읽어 갈 때도 아무것도 저장하지 않아요.

## 로컬에서 해 보기

Node 22 이상이 있으면 Cloudflare 없이 돌려 볼 수 있어요.

```bash
npm test                                  # 서버 테스트
node test/local-server.mjs 8787 &         # 메모리 KV로 띄우기
SHARE_TEST_URL=http://127.0.0.1:8787 ../../gradlew -p ../.. :app:testDebugUnitTest --tests '*ShareLinkTest*'
```

앱의 `ShareLinkTest`를 먼저 돌리면 앱이 만든 실제 근무표(`app/build/share-payload*.json`)를 `npm test`가 함께 검사해요.

## 앱 1.22부터: 신고·내리기·통계 [SRV-05][STAT-04]

- 공유 페이지 맨 아래에 **이 링크 신고하기**가 생겼어요. 스크립트 없는 폼이라 페이지는 여전히 스크립트를 쓰지 않아요.
  앱에서도 받은 달력의 메뉴로 `POST /api/share/:id/report`(`{reason}`)를 보내요. 이유는 `personal`(다른 사람의 개인정보), `abuse`(욕설·괴롭힘), `spam`(광고·스팸), `illegal`(불법 정보), `other`예요.
  누가 신고했는지는 남기지 않아요. 같은 사람이 같은 링크를 하루에 여러 번 신고해도 한 번으로 세고, 한 곳에서 한 시간에 10번까지 받아요.
- 신고 목록 보기와 링크 내리기는 회사 서버의 **개발자 앱 → 공유 링크 신고** 화면에서 해요. 내린 링크는 근무표를 바로 지우고, 90일 동안
  "운영 규칙에 따라 내려졌어요"(410)라고 답해요. 공유한 사람이 다시 고쳐 열 수는 없고, 새 링크는 만들 수 있어요.
- 날마다 만든 링크·페이지 열람·신고·내린 수를 `stats:YYYY-MM-DD`에 400일 동안 세요. KV 무료 쓰기 한도(하루 1,000번)를 아끼려고
  Worker가 5분마다 모아서 써요. 그래서 대략의 숫자예요.

| 요청 | 하는 일 |
| --- | --- |
| `POST /api/share/:id/report` | 앱의 신고. 답 204 |
| `POST /s/:id/report` | 페이지의 신고 폼 |
| `GET /api/admin/reports` | 신고된 링크(많은 순). 헤더 `Authorization: Bearer <SHARE_ADMIN_TOKEN>` |
| `DELETE /api/admin/share/:id` | 링크 내리기 |
| `GET /api/admin/stats?days=28` | 날마다의 숫자(1~90일) |

### 다시 올리기 전에 할 일

1. 이 폴더의 `src/index.js`를 위와 같이 다시 붙여 넣고 배포해요.
2. Worker → 설정 → 변수 및 비밀 → 추가. 유형 **비밀(Secret)**, 이름 `SHARE_ADMIN_TOKEN`, 값은 20자 넘는 아무 긴 글자(비밀번호 관리자에서 만든 것)예요.
3. 회사 서버 Worker에도 **같은 값**으로 `SHARE_ADMIN_TOKEN`(비밀)을, 그리고 `SHARE_BASE_URL`(텍스트, 예: `https://bamnat-share.<계정 이름>.workers.dev`)을 넣어요.
4. 넣지 않으면 관리 경로는 404로 숨어 있고, 개발자 앱은 "공유 서버가 아직 연결되지 않았어요"라고 보여 줘요.

`SHARE_ADMIN_TOKEN`은 비밀값이니 채팅이나 메신저로 보내지 마세요.

## 앱 1.23부터: 스위치·횟수·내린 이유·우리 조 모아 보기 [SRV-08][SHR-13][SHR-14]

- **연장은 끊기 열쇠를 가진 사람이면 누구나 할 수 있어요.** 서버는 프로인지 모르고(계정이 없어서), 180일·1년 연장을 프로에게만 여는 것은 앱이 해요(결정 D23). 열쇠는 링크를 만든 휴대폰(과 그 백업 파일)에만 있어요.
- 회사 서버 개발자 앱의 '근무표 링크 새로 만들기' 스위치를 끄면 **매시 정각 무렵**(회사 서버의 매시 작업, 최대 한 시간 늦음) 이 서버에도 `flag:create_off`가 써져서 옛 앱·직접 호출도 새 링크를 못 만들어요(503 `paused`). 있는 링크 보기·고치기·끊기는 그대로예요. 연결하려면 두 서버에 같은 `SHARE_ADMIN_TOKEN`, 회사 서버에 `SHARE_BASE_URL`이 있어야 해요.
- 횟수 제한(만들기 시간당 20, 신고 10, 모임 코드 10)은 Worker 안 메모리와 KV를 함께 봐요. 한 사람이 한꺼번에 몰아 보내면 한 Worker로 가서 정확히 막히고, 여러 Worker에 걸치면 KV가 원자적이지 않아 몇 번 더 열릴 수 있어요. 정확히 막으려면 Durable Object가 필요한데 무료 요금제 기준으로 만들어서 쓰지 않았어요.
- 구독 주소(`.ics`)는 ETag를 주고 5분만 저장하게 해요(전에는 15분). 내린 링크가 구독한 캘린더에서 더 빨리 빠져요.
- 운영자가 링크를 내릴 때 적은 이유(200자까지)를 내린 표시와 같이 90일 보관하고, 앱이 `GET /api/share/:id`로 물으면 410과 함께 `reason`을 돌려줘요. 공유한 사람 앱의 링크 카드에 그 이유가 보여요.
- **우리 조 모아 보기**: 각자 만든 링크를 6자 모임 코드로 묶어요. 서버는 `group:<코드>`에 링크 id 목록만 두고(이름·회사·만든 사람 없음), 링크마다 그 링크의 끊기 열쇠로만 넣고 빼요. 링크를 끊거나 내리면 묶음에서 바로 빠지고, 가장 늦게 끝나는 링크와 함께 묶음도 지워져요. 한 묶음에 12개까지예요.
- **앱 1.23을 내기 전에 이 서버 코드를 다시 올려 주세요.** 예전 서버는 모임 코드를 모르고(404), 내린 이유를 돌려주지 않아요.
