# 운영 달력 [ADMIN-14]

해마다 같은 달에 하는 운영 일입니다. 관리 앱 홈의 **이달 할 일**과 운영 화면이 이 표를 그대로 씁니다.
회사 서버의 `OPS_CALENDAR`와 이 표의 순서·키가 다르면 `test/operations.test.mjs`가 실패하므로, 한쪽을 고치면 다른 쪽도 같이 고칩니다.
체크 표시는 달마다 따로 저장되며(`settings`의 `ops:YYYY-MM`), 다음 해 같은 달에는 다시 비어 있습니다.

| 달 | 키 | 할 일 | 근거 |
| --- | --- | --- | --- |
| 1월 | `rates-new-year` | 새해 최저임금·4대 보험 요율이 앱 계산과 맞는지 확인 | 최저임금법 제10조 제2항(1월 1일 효력), 국민건강보험법 시행령 제44조(2026년 719/10,000), 노인장기요양보험법 시행령 제4조(2026년 9,448/1,000,000) |
| 1월 | `holidays-this-year` | 올해 공휴일·대체공휴일이 달력과 맞는지 확인 | 관공서의 공휴일에 관한 규정 제2조·제3조 |
| 2월 | `tax-table` | 근로소득 간이세액표가 바뀌었는지 확인(실수령 추정) | 소득세법 시행령 별표 2(개정 시기는 해마다 확인) |
| 3월 | `privacy-review` | 처리방침·데이터 보안 답안을 지금 서버와 대조 | 개인정보 보호법 제30조, [server-data.md](server-data.md) |
| 3월 | `incident-drill` | 유출 대응 절차서를 한 번 따라 해 보기(연락 순서·공지 문구) | 개인정보 보호법 제34조, [incident-response.md](incident-response.md) |
| 4월 | `android-preview` | 새 Android 미리보기에서 알람·알림 점검 | Google Play 대상 API 수준 요건(해마다 8월 31일) |
| 5월 | `store-listing` | 스토어 등록정보·화면 사진이 지금 앱과 맞는지 확인 | Google Play 메타데이터 정책 |
| 6월 | `pension-prepare` | 7월부터 쓰는 국민연금 기준소득월액 상하한 준비 | 국민연금법 시행령 제5조 |
| 7월 | `pension-apply` | 국민연금 상하한이 7월 급여부터 바뀌었는지 확인 | 국민연금법 시행령 제5조 |
| 8월 | `minwage-next` | 다음 해 최저임금 결정(8월 5일까지)을 앱에 넣을 준비 | 최저임금법 제8조 제1항 |
| 8월 | `target-api` | 대상 API 수준 마감(8월 31일) 전에 업데이트 출시 | Google Play 대상 API 수준 요건(2026-08-31부터 API 36) |
| 9월 | `holidays-next` | 다음 해 공휴일·대체공휴일·선거일 확인 | 관공서의 공휴일에 관한 규정 |
| 10월 | `health-next` | 다음 해 건강보험료율 결정 확인(결정 시기는 해마다 확인) | 국민건강보험법 시행령 제44조 |
| 11월 | `ltc-next` | 다음 해 장기요양보험료율 결정 확인 | 노인장기요양보험법 시행령 제4조 |
| 12월 | `release-new-year` | 새해 요율·최저임금·공휴일을 넣은 업데이트를 1월 1일 전에 출시 | 위 항목들 |
| 12월 | `server-data` | 서버 최소 데이터 점검(지울 것은 지우기) | 개인정보 보호법 제21조, [server-data.md](server-data.md) |

법령 본문은 국가법령정보센터(law.go.kr)에서 2026-10-22에 확인했습니다. 요율·날짜는 해마다 바뀌므로 표에는 "언제 확인하는지"만 적고, 실제 값은 앱 코드와 릴리스 노트에 남깁니다.
