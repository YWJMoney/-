# 개인정보 유출 대응 절차 (회사 서버·공유 서버)

[SRV-02] 처리방침 2.8의 8항에서 이 문서를 가리켜요. 근거는 개인정보 보호법 제34조(법률 제21445호, 2026-09-11 시행)와 같은 법 시행령 제39조·제39조의2·제39조의3·제40조(대통령령 제36671호, 2026-09-11 시행)예요. 2026-10-22에 국가법령정보센터 원문으로 대조했어요(`research/1.22-서버법령.md`).

이 문서에는 연락처, 비밀값, 계정 이름을 적지 않아요. 저장소가 공개라서예요. 비밀값을 바꾸는 방법은 각 서버의 README에 있어요.

## 0. 먼저 알아 둘 것

- **우리가 가진 것**: 서버에 있는 것은 `docs/server-data.md`의 표가 전부예요. 근무표 원본, 급여 내역, 이름, 전화번호, 메일 주소(운영자 계정 빼고)는 서버에 없어요.
- **연락처가 없어요**: 앱에는 회원가입이 없어 이용자에게 메일·문자로 알릴 길이 없어요. 그래서 법 제34조 ① 단서와 시행령 제39조 ③(가능성 통지는 제39조의3 ④)대로 **인터넷 홈페이지에 30일 이상 게시**하는 것으로 통지를 갈음하고, 같은 내용을 **앱 공지 한 줄**(관리자 앱 › 운영 › 공지, `/api/config`의 `notices`)로 함께 띄워요.
- **시계는 '알게 된 때'부터**: 통지·신고 모두 72시간이에요(시행령 제39조 ①, 제39조의3 ①, 제40조 ①).

## 1. 알게 된 즉시 (0~1시간): 막기

1. 시각을 적어요. 이 시각이 72시간의 시작이에요.
2. 퍼지는 것을 막아요. 해당하는 것만 해요.
   - **관리자 계정이 의심되면**: 관리자 앱 › 계정에서 그 계정을 정지(로그인 유지가 바로 끊김), 최고 관리자 비밀번호 바꾸기.
   - **서버 비밀값이 새었으면**: Cloudflare 대시보드에서 `RATE_SALT`, `ADMIN_PASSWORD`, `SHARE_ADMIN_TOKEN`, `MAIL_API_KEY`, `PLAY_SERVICE_ACCOUNT` 중 새은 것을 새 값으로 바꾸고 다시 배포.
   - **기능 하나가 문제면**: 관리자 앱 › 운영 › 기능 스위치로 그 기능을 잠시 꺼요(광장 글쓰기, 문의 사진, 근무표 링크 만들기 등). 앱은 '잠시 쉬고 있어요'를 보여 주고 서버를 부르지 않아요.
   - **공유 링크 하나가 문제면**: 관리자 앱 › 공유 링크 신고 › 내리기(공유 서버에서 바로 410).
   - **Cloudflare 계정이 의심되면**: 계정 비밀번호와 2단계 인증 다시 설정, API 토큰 모두 폐기.
3. 무엇이 나갔을 수 있는지 `docs/server-data.md`의 표로 좁혀요. 관리자 앱 › 작업 기록(1년 보관)과 Cloudflare의 Workers 로그를 봐요.

## 2. 판단 (1~24시간): 유출인가, 가능성인가

| 상황 | 법 | 할 일 |
| --- | --- | --- |
| 개인정보가 실제로 유출·분실·도난·위조·변조·훼손됨(유출등) | 법 제34조 ①, 시행령 제39조 | 3장 '통지' |
| 서버나 관리자 기기에 불법 접근이 있었고 유출이 의심되지만 누구 정보인지 특정하기 어려움 | 법 제34조 ② (2026-03-10 신설), 시행령 제39조의2 ①1호 | 3장 '가능성 통지' |
| 일부 정보가 불법 거래되는 등 유출이 확인되고 다른 사람 정보도 나갔을 수 있음 | 시행령 제39조의2 ①2호 | 3장 '가능성 통지' |
| 72시간 안에 실제 유출로 확인됨 | 시행령 제39조의3 ② | 가능성 통지 대신 유출 통지 |
| 가능성 통지 뒤 유출이 없었음을 확인 | 시행령 제39조의3 ③ | 즉시 '유출되지 않았어요' 게시 |

## 3. 통지 (72시간 안)

### 유출 통지에 넣을 것 (법 제34조 ① 1~7호)

1. 유출등이 된 개인정보의 항목(`server-data.md`의 표 이름과 열로)
2. 유출등이 된 시점과 경위
3. 피해를 줄이려고 이용자가 할 수 있는 것(예: 앱의 '이 휴대폰이 보낸 정보 모두 지우기', 링크 끊기, 문의 지우기)
4. 운영자의 대응 조치와 피해 구제 절차
5. 피해 신고를 받는 곳: 앱 › 설정 › 도움말과 문의, 처리방침 8항의 메일
6. 손해배상(법 제39조)·법정손해배상(제39조의2)·분쟁조정(제43조) 같은 법적 권리와 행사 방법
7. 그 밖에 대통령령으로 정한 사항

구체적인 항목이나 시점을 아직 모르면, 유출된 사실과 그때까지 확인된 것, 3~6호를 **먼저** 알리고 확인되는 대로 더해요(시행령 제39조 ②).

### 가능성 통지에 넣을 것 (시행령 제39조의2 ②)

1. 유출등의 가능성이 있는 항목
2. 유출이 있었을 것으로 의심되는 시점과 경위
3. 위 3~5호
4. 유출이 확정되면 다시 알린다는 것

### 어떻게

1. **게시 페이지**: 저장소 루트에 `notice/<날짜>.html`을 만들고 처리방침 맨 위에 링크를 걸어 GitHub Pages로 올려요. 30일 넘게 그대로 둬요(시행령 제39조 ③, 제39조의3 ④).
2. **앱 공지**: 관리자 앱 › 운영 › 공지 쓰기. 중요도 '중요', 기간 31일, 제목 한 줄과 본문 500자 안에 요점과 게시 페이지 주소.
3. 긴급 조치가 먼저 필요해 72시간 안에 못 하면, 그 사유가 풀린 뒤 즉시 해요(시행령 제39조 ① 단서). 그 사유를 기록해 둬요.

## 4. 신고 (72시간 안)

아래 중 **하나라도** 맞으면 개인정보보호위원회 또는 한국인터넷진흥원(KISA)에 신고해요(시행령 제40조 ①, ③).

- 1천 명 이상의 정보주체에 관한 개인정보가 유출등이 된 경우
- 민감정보 또는 고유식별정보가 유출등이 된 경우(우리 서버에는 없도록 막았지만, 문의 글·사진에 이용자가 적었을 수 있음)
- 개인정보처리시스템이나 관리자 기기에 **외부로부터의 불법 접근**으로 유출등이 된 경우 — Cloudflare 계정·관리자 계정 탈취는 규모와 관계없이 여기에 들어요

신고 내용은 통지의 1~7호와 같아요. 모르는 것은 먼저 아는 데까지, 확인되는 대로 더해요(제40조 ②). 경로가 확인되어 회수·삭제로 침해 가능성이 현저히 낮아진 경우에는 신고하지 않을 수 있지만(제40조 ① 단서), 그 판단 근거를 기록으로 남겨요.

신고 창구는 개인정보 포털(privacy.go.kr)의 유출 신고와 KISA 118 상담이에요. 창구 주소는 신고하는 날 다시 확인해요.

## 5. 뒤처리

1. 막은 것을 되돌릴 때: 기능 스위치를 다시 켜고, 공지를 내려요(게시 페이지는 30일 지난 뒤).
2. 원인을 고친 판을 내고, 무엇을 바꿨는지 이 문서 아래 '기록'에 적어요.
3. 처리방침이나 `server-data.md`가 바뀌면 고쳐요.
4. 관리자 앱 작업 기록은 1년 뒤 저절로 지워지므로, 사고와 관련된 기록은 내려받아 사고 기록과 함께 둬요(법 제29조, 시행령 제30조 ① 5호의 접속기록 보관 취지).
